# Локальный ИИ-стек: самохостинг моделей (решение принято)

Статус: **решение принято** — заказчик не хочет зависеть от внешних LLM-сервисов, целевая точка — «своя нейросеть». Этот документ описывает, как это сделать честно и с запасом на рост.

Исходные данные:
- Сейчас: ноутбук на Windows, Intel Core i7, встроенная графика — **всё локально**.
- Потом: **VPS** (при росте нагрузки/качества — VPS с GPU).
- Принцип: ни один запрос пользователя не уходит во внешние AI-сервисы.

---

## 1. Общая схема

```
Backend (Rust) ──► LlmProvider (OpenAI-совместимый HTTP) ──► локальный рантайм моделей
                                                              ├── dev:  Ollama (Windows) или
                                                              │         llama.cpp llama-server (WSL2/Docker)
                                                              └── prod: llama.cpp / Ollama в Docker Compose на VPS
                                                                        (при GPU — llama.cpp CUDA или vLLM)
```

Ключевой момент: локальные рантаймы (Ollama, llama.cpp) **уже** предоставляют OpenAI-совместимый API. Поэтому абстракция `LlmProvider` из общей архитектуры не меняется — мы просто указываем ей локальный адрес вместо облачного. Миграция «ноутбук → VPS → GPU» — это смена URL и модели, **не переписывание кода**.

## 2. Что на чём считается

| Задача | Чем решается | Потребности |
|--------|-------------|-------------|
| Диалог наставника (генерация текста) | Локальная LLM 4–14B (квантизация Q4), стриминг | самая тяжёлая часть |
| Извлечение фактов о пользователе, роутинг намерений | Маленькая модель (3–4B) или правила | дёшево, можно пачками в фоне |
| Эмбеддинги для памяти (семантический поиск) | **bge-m3** или multilingual-e5 — локально, CPU | быстро (~сотни запросов/сек) |
| Конфликты расписания, таймеры, XP, правдоподобие времени | Чистый Rust, **без ИИ** | без изменений |
| Модерация и кризисные фразы | Правила + локальный классификатор | без изменений |
| Голос (Фаза 3) | **whisper.cpp** (small/medium, CPU) + локальный TTS (**Piper**) | тоже без внешних сервисов |
| Компьютерное зрение (Фаза 2–3) | MediaPipe **на Android-устройстве** | на сервер ничего не приходит |

## 3. Стартовые модели (рекомендации)

Выбор модели зависит от ОЗУ ноутбука (см. вопрос ниже). Все — квантизированные GGUF Q4_K_M, запускаются через Ollama/llama.cpp:

| ОЗУ | Рабочая модель диалога | Комфорт | Заметки |
|-----|------------------------|---------|---------|
| 8 ГБ | Qwen3-4B (или Gemma 3-4B) | быстро, качество базовое | 8B при 8 ГБ в тесноте (Windows + IDE + БД) |
| 16 ГБ | **Qwen3-8B** | оптимум «скорость/качество» | Gemma 3-12B — на грани, при закрытых лишних программах |
| 32+ ГБ | Gemma 3-12B / Qwen3-14B | лучшее качество диалога | комфортно с полным стеком |

Ориентировочные скорости на CPU (Core i7, двухканальная память; цифры примерные, проверим фактически):

| Модель | Скорость | Ощущение |
|--------|----------|----------|
| 4B Q4 | ~12–20 токенов/сек | ответ почти сразу |
| 8B Q4 | ~6–12 токенов/сек | ответ «печатается» ~20–40 сек |
| 12–14B Q4 | ~4–8 токенов/сек | медленно, но со стримингом терпимо |

По русскому языку среди малых моделей лучше всего себя показывают **Qwen3** и **Gemma 3** (многоязычность); Llama малых размеров слабее по русскому. Рекомендация на старт: **Qwen3-8B** как рабочая лошадка + сравнить с Gemma 3-12B, если память позволяет. (К моменту старта проверим и более новые модели из тех же семейств.)

## 4. Честные ограничения (прочитать обязательно)

1. **Качество диалога 4–14B ниже, чем у облачных флагманов.** Тонкие реакции характера, длинные рассуждения, сложное следование инструкциям — будут проще. Компенсации: сильные версионируемые промпт-шаблоны, few-shot примеры характера, короткий контекст + RAG по памяти, действия — строго структурированные (JSON), а не «свободный текст с надеждой».
2. **Скорость на CPU.** Развёрнутый ответ наставника в 300 токенов при 8 ток/сек ≈ 35–40 секунд. Стриминг в UI обязателен; фоновые задачи (сводки, консолидация памяти, отчёты) идут пачками и вне интерфейса — их медленность не видна пользователю.
3. **Потолок нагрузки ноутбука.** Один пользователь — комфортно. Несколько одновременных диалогов на CPU уже тяжело; коммерческий запуск на аудиторию требует VPS с GPU. Это и есть точка «купаю VPS».
4. **ОЗУ — главный лимит.** Модель + Postgres + Redis + бэкенд + Android Studio на одной машине. При 8 ГБ придётся жить с 4B и закрывать лишнее; 32 ГБ — полная свобода.
5. **Встроенная графика Intel** (SYCL/OpenVINO в llama.cpp) — можно поэкспериментировать позже, но базовый путь — **CPU**: он предсказуем и не требует возни с драйверами.

## 5. Путь миграции (задел на рост, без переписывания)

| Шаг | Где | Модели | Для кого |
|-----|-----|--------|----------|
| 1. Разработка | Ноутбук (Windows/WSL2) | Qwen3-8B Q4, bge-m3 | ты, один пользователь |
| 2. Первый запуск | VPS без GPU (8–16 ядер) | 7–14B Q4 | несколько пользователей |
| 3. Рост | VPS **с GPU** (например, RTX 4090/L4) | 14–32B Q4/Q5; vLLM или llama.cpp CUDA | десятки–сотни пользователей |
| 4. «Своя нейросеть» | Аренда GPU по часам (обучение) + свой VPS (инференс) | **LoRA-дообучение** базовой модели на данных использования (обезличенно, с согласия) | своя уникальная модель наставника |

Про шаг 4 подробнее — это и есть реализация «своей нейросети, но не с нуля»:
- Берём открытую базовую модель (Qwen3/Gemma 3), собираем датасет из диалогов и решений наставника (с согласия пользователей, обезличенно, с возможностью opt-out).
- Дообучаем LoRA-адаптер (несколько часов аренды GPU, копейки) — получаем **модель со своим характером и стилем**, которая работает на нашем рантайме.
- Повторяем периодически; никакой зависимости от чужих API на любом шаге.

## 6. Dev-окружение на Windows

- **WSL2 + Docker Desktop** — Postgres 16 (+pgvector), Redis, llama.cpp server, backend — всё в Docker Compose (паритет с будущим деплоем на VPS).
- **Rust-тулчейн** — в WSL2 (та же среда, что на Linux-сервере).
- **Ollama нативный на Windows** — самый простой способ скачать и запустить модели для пробы (альтернатива llama.cpp в Docker).
- **Android Studio** — нативно на Windows; физический телефон/эмулятор достучится до бэкенда по адресу в локальной сети (`10.0.2.2` для эмулятора, LAN-IP для телефона).

## 7. Стартовый конфиг (Фаза 0, после подтверждения)

`docker-compose.yml`:
- `postgres:16` + расширение `pgvector` — данные + память;
- `redis` — сессии, кэш, очереди;
- `llama-server` (llama.cpp) — модель скачивается в volume;
- `backend` (Rust, наш);
- (позже) `whisper`, `piper` — для голоса.

Модель по умолчанию: **Qwen3-8B Q4_K_M** (или под ОЗУ ноутбука), эмбеддинги: **bge-m3**.
