# Развёртывание на VPS — подробная пошаговая инструкция

**Для кого:** VPS на Ubuntu 24.04, 2 vCPU, 4 ГБ ОЗУ, 120 ГБ диска (подстройки под другие конфигурации помечены).
**Что получим:** работающий сервер «Ментора» с HTTPS, локальной нейросетью-наставником, бэкапами — и приложение на телефоне, подключённое к нему.
**Время:** 40–80 минут (включая скачивание модели ~2.5 ГБ).

> Перед началом: **никогда не присылайте пароли, токены и секреты в чат** (в том числе мне). Всё, что в кавычках `вот так`, — вы выполняете сами на своём компьютере/VPS.

## Шаг 1 — Подключение к VPS

У вас есть IP-адрес сервера, логин (обычно `root`) и пароль — они пришли от провайдера (Play2Go) на почту или в личный кабинет.

**Windows 10/11** (встроенный SSH-клиент):
1. Откройте **PowerShell** (Пуск → введите "PowerShell").
2. Команда (замените IP на свой):
   ```powershell
   ssh root@ВАШ_IP
   ```
3. При первом подключении спросит `Are you sure you want to continue connecting?` → введите `yes`, Enter.
4. Введите пароль root (при вводе символы не отображаются — это нормально), Enter.

Успешное подключение — вы видите приглашение вида `root@vps:~#`.

> Альтернатива: программа [PuTTY](https://www.putty.org/) — Host Name = IP, Port = 22, кнопка Open.

**Смените пароль root** (если он пришёл автоматически сгенерированным):
```bash
passwd
```
Введите новый пароль дважды. Запишите его в надёжное место (менеджер паролей).

## Шаг 2 — Первичная настройка сервера

Проект содержит готовый скрипт настройки. Но сначала — сам проект на сервер (скрипт внутри него):

```bash
apt-get update && apt-get install -y git
git clone https://github.com/naaacleee/proj.git /opt/mentor
cd /opt/mentor/deploy
bash scripts/vps-setup.sh
```

Что делает скрипт (можно выполнить и руками, если не доверяете автоматике):
1. Обновляет систему (`apt upgrade`).
2. Ставит базовые пакеты: `curl`, `git`, `ufw` (фаервол).
3. Создаёт **swap-файл 4 ГБ** — страховку для ОЗУ, критически важную для работы нейросети на 4 ГБ.
4. Устанавливает **Docker** (официальным скриптом) и включает его в автозагрузку.
5. Включает фаервол: открыты только SSH (22), HTTP (80), HTTPS (443).

⚠️ **Если git clone не проходит** (репозиторий приватный):
- **Вариант А (проще):** временно сделайте репозиторий публичным на GitHub (Settings → Danger Zone → Change visibility), склонируйте, потом верните как было.
- **Вариант Б (правильнее):** создайте на GitHub **Personal Access Token** (Settings → Developer settings → Fine-grained tokens → только чтение репозитория proj) и используйте **сразу на сервере**, не отправляя его в чат:
  ```bash
  git clone https://ВАШ_ТОКЕН@github.com/naaacleee/proj.git /opt/mentor
  ```
  После клонирования уберите токен из URL:
  ```bash
  cd /opt/mentor && git remote set-url origin https://github.com/naaacleee/proj.git
  ```

⚠️ **Фаервол в панели провайдера.** У ряда провайдеров (включая игровые/бюджетные хостинги, к которым относится Play2Go) помимо серверного `ufw` есть **свой фаервол в личном кабинете**. Зайдите в панель управления сервером и убедитесь, что открыты (или стоят правила "Allow" для):
- TCP 22 (SSH), TCP 80 (HTTP), TCP 443 (HTTPS).
Если панели такого нет — ничего делать не нужно. **Это первое место проверять, если сайт позже не откроется.**

**Проверка:** выполните `ufw status` — должны увидеть правила 22, 80, 443.

## Шаг 3 — Бесплатный домен через DuckDNS

HTTPS-сертификат выдаётся на **доменное имя**, а не на IP. DuckDNS даёт бесплатный поддомен вида `что-то.duckdns.org`.

1. Откройте **https://www.duckdns.org** на компьютере и войдите (кнопка входа через Google/GitHub/Twitter — любой).
2. В поле **"domain"** придумайте имя (например, `mentor-ivan-2026`) и нажмите **"add domain"**. Получится адрес `mentor-ivan-2026.duckdns.org`.
3. В поле **"current ip"** вставьте IP вашего VPS и нажмите **"update ip"** (или кнопку "update ip" с уже подставленным IP).
4. Сохраните **TOKEN** — он показан крупно вверху страницы. Он понадобится только для авто-обновления IP (Шаг 3.1) — **в чат не отправляйте**.

**Проверка** (в PowerShell на компьютере):
```powershell
ping mentor-ivan-2026.duckdns.org
```
Должен пинговаться IP вашего VPS.

### Шаг 3.1 — Авто-обновление IP (необязательно)

IP у VPS обычно постоянный, но на случай его смены DuckDNS рекомендует cron-задачу. На сервере:

```bash
mkdir -p /etc/duckdns
echo 'echo url="https://www.duckdns.org/update?domains=ВАШ_ПОДДОМЕН&token=ВАШ_ТОКЕН&ip=" | curl -k -o /etc/duckdns/duck.log -K -' > /etc/duckdns/duck.sh
chmod 700 /etc/duckdns/duck.sh
(crontab -l ; echo "*/5 * * * * /etc/duckdns/duck.sh >/dev/null 2>&1") | crontab -
```
(Замените `ВАШ_ПОДДОМЕН` и `ВАШ_ТОКЕН` на значения с сайта DuckDNS. Токен вводится прямо в команду на сервере — это безопасно, в чат его не нужно.)

## Шаг 5 — Секреты и файл .env

1. Создайте рабочий конфиг из шаблона:
   ```bash
   cp .env.example .env
   ```
2. Сгенерируйте пароль базы и секрет подписи токенов (выполняйте по одной):
   ```bash
   openssl rand -base64 24
   openssl rand -base64 48
   ```
   Каждая выведет случайную строку — **запишите их**.
3. Откройте файл для редактирования:
   ```bash
   nano .env
   ```
   (`nano` — простой редактор: стрелки двигают курсор, `Ctrl+O` — сохранить, `Enter` — подтвердить, `Ctrl+X` — выйти.)
4. Заполните значения (ориентир для вашего VPS — **4 ГБ ОЗУ, 2 vCPU**):

   | Переменная | Ваше значение | Комментарий |
   |---|---|---|
   | `DOMAIN` | `mentor-ivan-2026.duckdns.org` | ваш поддомен DuckDNS, **без** `https://` |
   | `ADMIN_EMAIL` | ваш email | для уведомлений о сертификатах |
   | `POSTGRES_PASSWORD` | строка из `openssl rand -base64 24` | пароль базы |
   | `MENTOR_JWT_SECRET` | строка из `openssl rand -base64 48` | секрет токенов |
   | `LLM_CHAT_MODEL` | `qwen3:4b` | модель-наставник (4B — под 4 ГБ ОЗУ) |
   | `LLM_THREADS` | `2` | по числу vCPU |
   | `LLM_CONTEXT` | `4096` | меньше контекст = экономнее память |
   | `LLM_MEMORY_LIMIT` | `3g` | потолок памяти контейнера модели |

5. Ограничьте доступ к файлу (в нём секреты):
   ```bash
   chmod 600 .env
   ```

## Шаг 6 — Скачивание нейросети (модели)

Модель — один файл ~2.5 ГБ в формате GGUF. Для вашего VPS подходит **Qwen3-4B, квантизация Q4_K_M**.

```bash
cd /opt/mentor/deploy/models
wget -O model.gguf "https://huggingface.co/Qwen/Qwen3-4B-GGUF/resolve/main/qwen3-4b-q4_k_m.gguf"
```

Скачивание займёт 1–5 минут (NVMe + быстрый канал). Проверка:

```bash
ls -lh model.gguf
```
Размер ~2.5 ГБ (2 000–3 000M). Файл НЕ попадает в git — это нормально.

⚠️ **Если ссылка не сработала** (имена файлов на Hugging Face иногда отличаются):
1. Откройте в браузере `https://huggingface.co/Qwen/Qwen3-4B-GGUF/tree/main`.
2. Найдите файл, в имени которого есть `q4_k_m` (пример: `qwen3-4b-q4_k_m.gguf`).
3. Нажмите на него → кнопка **Download** → правой кнопкой → «Копировать адрес ссылки».
4. На сервере: `wget -O model.gguf 'ВСТАВЬТЕ_ССЫЛКУ'`.

Также подойдут любые GGUF-версии **Qwen3-4B** или **Gemma 3-4B** в квантизации `Q4_K_M` от любых издателей (bartowski, unsloth и др.).

### Вариант Б — Ollama вместо llama.cpp (если хочется проще)

Вместо Шага 6 можно поставить Ollama прямо на сервер:
```bash
curl -fsSL https://ollama.com/install.sh | sh
```

## Шаг 7 — Запуск сервера

**Первый запуск — без модели** (так проще искать проблемы, если они будут):
```bash
cd /opt/mentor/deploy
docker compose -f docker-compose.prod.yml up -d --build
```
Разбор команды: `docker compose` — оркестратор контейнеров; `-f docker-compose.prod.yml` — какой конфиг использовать; `up -d` — поднять и работать в фоне; `--build` — сначала собрать бэкенд из исходников (первый раз 5–15 минут, Rust компилируется).

**Затем — вместе с нейросетью:**
```bash
docker compose -f docker-compose.prod.yml --profile ai up -d
```
(Если использовали вариант Б с Ollama — эта команда не нужна.)

Посмотреть, что поднялось:
```bash
docker compose -f docker-compose.prod.yml ps
```
У `db`, `redis`, `backend`, `caddy` (и `llama`) статус должен быть `running`/`Up` (у backend — `(healthy)`).

## Шаг 8 — Проверка работы

**1. Проверка с сервера:**
```bash
curl http://127.0.0.1:8080/healthz
```
Ответ: `ok`.

**2. Проверка HTTPS через домен** (сертификат выпускается автоматически за ~30–60 секунд после первого обращения):
```bash
curl https://ВАШ_ПОДДОМЕН.duckdns.org/healthz
```
Ответ: `ok`. Если сначала ошибка сертификата — подождите минуту и повторите.

**3. Регистрация тестового пользователя:**
```bash
curl -X POST https://ВАШ_ПОДДОМЕН.duckdns.org/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"username":"testuser","password":"supersecret123"}'
```
В ответе JSON с `access_token` и `refresh_token` — сервер работает.

**4. Тест диалога с наставником** (подставьте `access_token` из ответа выше):
```bash
curl -X POST https://ВАШ_ПОДДОМЕН.duckdns.org/api/v1/mentor/chat \
  -H "Authorization: Bearer ВСТАВЬТЕ_ТОКЕН" \
  -H 'Content-Type: application/json' \
  -d '{"message":"Привет! Кто ты?"}'
```
⚠️ **Первый ответ модели приходит 30–90 секунд** (2 vCPU, CPU-инференс) — это нормально для вашего сервера. Дальше будет быстрее (модель кэшируется в памяти).

**5. Логи (если интересно или что-то не так):**
```bash
docker compose -f docker-compose.prod.yml logs -f backend
docker compose -f docker-compose.prod.yml logs -f llama
```
(`Ctrl+C` — выйти из просмотра логов.)

## Шаг 9 — Приложение на телефоне

**1. Соберите APK на компьютере** (нужен установленный Android Studio, см. README):
- Откройте папку `android/` проекта в Android Studio.
- Меню **Build → Build Bundle(s) / APK(s) → Build APK(s)**.
- Дождитесь `BUILD SUCCESSFUL`, нажмите **locate** — появится файл `app-debug.apk`.

**2. Перенесите APK на телефон:** USB-кабель (папка «Загрузки»), или отправьте файл себе в мессенджер/облако и откройте на телефоне.

**3. Установите:** на телефоне разрешите установку из неизвестных источников (при запросе), откройте файл → «Установить».

**4. Настройте приложение:**
- Откройте «Ментор» → вкладка **Настройки** → поле «Адрес бэкенда» → введите:
  ```
  https://mentor-ivan-2026.duckdns.org
  ```
  (ваш поддомен, **с** `https://`) → «Сохранить адрес».
- На вкладке **Чат** или экране входа нажмите «Создать аккаунт» — приложение зарегистрирует вас на сервере.
- Поздоровайтесь с наставником в чате! Ответы идут с вашей личной нейросети на вашем VPS.

> Телефон должен быть в интернете (мобильный интернет тоже подходит — домен доступен отовсюду).

## Шаг 10 — Бэкапы базы данных

Настройте ежедневный дамп (см. комментарий в `scripts/backup-db.sh`):

```bash
crontab -e
```
(При первом запуске спросит редактор → выберите `1` = nano.) Добавьте строку в конец:
```
30 3 * * * cd /opt/mentor/deploy && bash scripts/backup-db.sh >> /var/log/mentor-backup.log 2>&1
```
Сохраните (`Ctrl+O`, `Enter`, `Ctrl+X`). Дампы будут в `/var/backups/mentor/`, хранятся 14 дней.

**Ручная проверка:**
```bash
cd /opt/mentor/deploy && bash scripts/backup-db.sh && ls -lh /var/backups/mentor/
```

## Шаг 12 — Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Сайт не открывается вообще (таймаут) | **Фаервол в панели Play2Go** — открыты ли 80/443; `ufw status` на сервере; `docker compose -f docker-compose.prod.yml ps` — все ли контейнеры Up |
| `curl https://домен/healthz` → ошибка сертификата | Подождите 1–2 минуты после первого запуска; `docker compose logs caddy` — там видно выпуск Let's Encrypt; проверьте, что домен пингуется на IP сервера |
| `502 Bad Gateway` | Бэкенд не поднялся: `docker compose logs backend` |
| Модель не отвечает / ошибка `model error` | `docker compose logs llama`; проверьте, что `models/model.gguf` существует и имеет размер ~2.5 ГБ |
| Контейнер llama перезапускается (OOM) | Мало памяти: в `.env` уменьшите `LLM_CONTEXT=2048` и `LLM_MEMORY_LIMIT=2600m`, затем `docker compose -f docker-compose.prod.yml --profile ai up -d`; проверьте swap: `free -h` (строка Swap должна быть ~4 ГБ) |
| Ответы ИИ очень медленные | Нормально для 2 vCPU: 30–90 секунд на длинный ответ. Можно уменьшить `LLM_CONTEXT`, ответы станут быстрее |
| Телефон не подключается | В настройках приложения — полный адрес с `https://`; телефон в интернете; попробуйте открыть `https://домен/healthz` в браузере телефона |
| «Не удалось установить APK» | На телефоне разрешите установку неизвестных приложений для браузера/файлов |

**Полезные команды диагностики:**
```bash
docker compose -f docker-compose.prod.yml ps          # состояние контейнеров
docker compose -f docker-compose.prod.yml logs -f     # все логи (Ctrl+C — выход)
free -h                                                # память и swap
df -h                                                  # диск
docker stats --no-stream                               # потребление ресурсов
```

## Чек-лист безопасности

- [x] Фаервол `ufw` включён (делает скрипт), наружу — только 22/80/443.
- [x] Postgres и Redis **не** доступны из интернета (внутренняя сеть Docker).
- [x] HTTPS с валидным сертификатом (Let's Encrypt, авто-продление).
- [x] Секреты (`MENTOR_JWT_SECRET`, `POSTGRES_PASSWORD`) сгенерированы случайно, файл `.env` с правами 600.
- [x] База бэкапится ежедневно.
- [ ] Рекомендуется: вход по SSH-ключам вместо пароля (см. `ssh-keygen` + `ssh-copy-id`, затем в `/etc/ssh/sshd_config` → `PasswordAuthentication no`).
- [ ] Рекомендуется: авто-обновления безопасности — `apt-get install -y unattended-upgrades && dpkg-reconfigure -plow unattended-upgrades`.
- [ ] Рекомендуется: `apt-get install -y fail2ban` — защита SSH от перебора.
